# nebo — самолётное табло на Raspberry Pi

Памятка для Claude Code. Собрана из обсуждения в чате, чтобы не пересказывать заново.
Всё, что помечено «проверить», — предположение, а не установленный факт.

## Имена

- Проект называется `nebo`.
- Папка проекта на Mac: `~/nebo`.
- Имя хоста малинки: `nebo` (в сети — `nebo.local`). Если на карте сейчас другое
  имя, переименовать после первого входа или задать при записи карты.
- systemd-сервис программы: `nebo.service`.

## Цель

Настольное табло, которое показывает, какие самолёты сейчас пролетают рядом:
номер рейса, откуда → куда, высота, расстояние.

Этапы:
1. ✅ Прототип на Raspberry Pi 4 с сенсорным экраном 3,2", данные из интернета.
2. ✅ Свой приём ADS-B через RTL-SDR, данные локальные (с 2026-10-20), плюс веб-страница.
3. Возможно потом: большая LED-панель HUB75 на стену и отправка данных в Flightradar24.

## Пользователь

- Опытный Linux-администратор (systemd, сети, Docker и т. д.), объяснять Linux не нужно.
- В электронике новичок: термины по железу (GPIO, I2C, SPI, HUB75 и т. п.)
  объяснять простыми словами, без аббревиатур без расшифровки.
- На его Mac `grep` подменён на ripgrep: вместо `grep -E` использовать `rg`
  или `command grep`.
- macOS в выводе `arp -a` отбрасывает ведущие нули в MAC-адресах.
- Предпочитает аккуратные изменения конфигов вручную, а не скрипты производителя,
  которые перезаписывают файлы целиком.
- Общение на русском.

## Текущее состояние

Проверено 2026-10-11:

- Доступ: `ssh <адрес малинки>` (Wi-Fi), пользователь `xtreme`, ключи, sudo без пароля.
  Адреса, домены и точные координаты — в `CLAUDE.local.md` (не публикуется; в этом файле вместо них заглушки).
- Raspberry Pi 4 Model B Rev 1.5, 8 ГБ. Raspberry Pi OS Lite 64-bit на Debian 13 (trixie),
  ядро 6.18 (rpt-rpi-v8), Python 3.13. Без графической оболочки (multi-user.target).
- Имя хоста переименовано `piscreen` → `nebo`. Карту записывал Imager через cloud-init:
  имя правится ещё и в `/boot/firmware/user-data` (там `manage_etc_hosts: true`),
  иначе `/etc/hosts` пересоберётся со старым именем.
- Бэкапы оригиналов: `/boot/firmware/config.txt.orig`, `/boot/firmware/user-data.orig`.

Экран 3,2" работает на штатных оверлеях (LCD-show и сторонние `.dtbo` не нужны).
В конце `/boot/firmware/config.txt`:

    dtparam=spi=on
    dtoverlay=fbtft,spi0-0,waveshare32b,dc_pin=22,reset_pin=27,rotate=270
    dtoverlay=ads7846,cs=1,penirq=17,speed=2000000,xohms=60,pmax=255,swapxy,invx
    dtoverlay=gpio-key,gpio=18,active_low=1,gpio_pull=up,keycode=103,label=nebo-up
    dtoverlay=gpio-key,gpio=23,active_low=1,gpio_pull=up,keycode=28,label=nebo-enter
    dtoverlay=gpio-key,gpio=24,active_low=1,gpio_pull=up,keycode=108,label=nebo-down

В `/boot/firmware/cmdline.txt` добавлено `fbcon=map:9` — текстовая консоль не выводится
на маленький экран (иначе getty рисует логин поверх картинки). Бэкап: `cmdline.txt.orig`.

- Картинка: `/dev/fb0`, имя `fb_ili9340`, 320×240, RGB565 (16 бит, little-endian),
  SPI 48 МГц. Цвета правильные, `bgr` трогать не нужно.
- `rotate=270` — разъём питания малинки сверху, кнопки экрана слева.
- Если подключить HDMI, номер framebuffer может сдвинуться; программе искать
  устройство по имени в `/sys/class/graphics/fb*/name`.
- Номера `/dev/input/eventN` плавают — искать устройства по имени в
  `/sys/class/input/event*/device/name`.
- Тач: `ADS7846 Touchscreen`. Ориентация исправлена в ядре (`swapxy,invx`): X растёт
  вправо, Y вниз. Пересчёт в пиксели — в программе (ядро при `invx` считает `max − x`
  без учёта минимума, поэтому диапазон в оверлей не вносить). Калибровка 2026-10-11:
  X 120 → 3746 (0 → 320 px), Y 253 → 4043 (0 → 240 px), точность ~3 px.
  Перекалибровка: `sudo python3 ~/nebo/tools/touch_calibrate.py` (исходник в `tools/`).
- Три кнопки слева от экрана (оверлей `gpio-key`, нажата = 0, подтяжка в оверлее):
  верхняя — GPIO18 (ножка 12) → KEY_UP (103), имя устройства `button@12`;
  средняя — GPIO23 (ножка 16) → KEY_ENTER (28), `button@17`;
  нижняя — GPIO24 (ножка 18) → KEY_DOWN (108), `button@18`.
  В имени устройства номер GPIO в шестнадцатеричном виде.
- Программа должна захватывать кнопки и тач через `EVIOCGRAB`, иначе нажатия
  уходят в консоль tty1 (Enter попадает в getty).
- `/tmp` на trixie — tmpfs, очищается при перезагрузке. Файлы проекта на малинке — в `~/nebo`.
- Экран снимать и надевать только при выключенной малинке. Белый экран =
  подсветка есть, инициализации нет (плохо сел на гребёнку или переставлен на ходу).

## План

1. ✅ Найти малинку, зайти по SSH, выяснить версию ОС и ядра.
2. ✅ Подключить экран 3,2" (штатные `fbtft` + `ads7846` + `gpio-key`, см. выше).
   Исходный план:
   - не запускать скрипты LCD-show;
   - положить нужный `.dtbo` в `/boot/firmware/overlays` и добавить строку
     `dtoverlay=...` в `/boot/firmware/config.txt`;
   - кандидат — оверлей `waveshare32b` (в стандартной поставке его нет) — проверить,
     подходит ли к этому клону, и нет ли подходящего штатного оверлея;
   - убедиться, что появился framebuffer (`/dev/fb1` или DRM-устройство) и работает тач.
3. ✅ Программа `nebo` (Python + Pillow + numpy, без браузера) — первая версия работает
   как `nebo.service` с 2026-10-11. Подробности — в разделе «Программа» ниже.
4. ✅ Источник данных: adsb.lol `/v2/point/{lat}/{lon}/{radius_nm}` (радиус в морских милях,
   ключ не нужен, формат как у readsb). Маршруты: adsbdb.com `/v0/callsign/{callsign}`.
   Маршрутный эндпоинт adsb.lol `/api/0/routeset` на 2026-10-11 отвечает 201 с пустым телом —
   не использовать. Неофициальный API Flightradar24 не использовать как основной.
5. ✅ Источник сменный: `[source] type = "readsb"` + `path` (файл или http-адрес aircraft.json).
   С 2026-10-20 на малинке — свой приёмник (см. «Приёмник ADS-B на малинке»), `interval = 2`.
   Старый конфиг с adsb.lol: `/etc/nebo/config.toml.bak-adsblol`.
   Режим без антенны (`type = "adsblol"`, по умолчанию в config.example.toml) проверен 2026-11-05 второй копией
   на малинке: табло, страница, AR, маршруты работают; нет статистики приёма, контура дальности и судов —
   страница судов в этом режиме пишет «Суда видны только со своей антенной» (`own_receiver` в /api/ships).
   В подвале страницы — атрибуция adsb.lol (ODbL). Без экрана 3,2" nebo пока не запускается (нужен framebuffer).
6. ✅ Координаты и радиус — в `/etc/nebo/config.toml`. Дом — в Лимассоле
   (точные координаты — в CLAUDE.local.md). `radius_km` (80) — только радиус запроса к adsb.lol.
   Со своим приёмником табло показывает всё принятое (решение пользователя 2026-10-20),
   масштаб карты на табло — круглое число, в которое входят выбранный борт и 80 % остальных
   (`_map_radius()` в `app.py`), борты дальше масштаба на карте не рисуются.

## Программа

- Код на Mac: `nebo/` (пакет), `nebo/data/` (справочники и карта), `tools/`, `deploy/nebo.service`,
  `config.example.toml`. Выкладка: `./deploy.sh` (rsync в `~/nebo` на малинке, обновляет юнит,
  перезапускает сервис; конфиг `/etc/nebo/config.toml` не трогает). Хост — переменная `NEBO_HOST`.
- Репозиторий: приватный (ветка `main`, с 2026-10-13, вся история; адрес — в CLAUDE.local.md).
  GPL-кода больше нет (силуэты tar1090 заменены своими 2026-10-19). Лицензия — MIT (2026-11-05).
- Публичный репозиторий (2026-11-05, решение пользователя): отдельный, с одним чистым первым коммитом —
  https://github.com/ii-shenky/nebo — чтобы ник пользователя не светился в ссылках (почта в коммитах — можно, решение пользователя). Проект открыто подаётся как написанный с Claude Code: CLAUDE.md публикуется,
  история диалога — в `ai/` (`tools/export_context.py --scrub .scrub`). Не публикуется (в .gitignore):
  `CLAUDE.local.md` (адреса, домены, Cloudflare, точные координаты, почта), `.scrub`, `nebo/data/aip_lccc.json`
  (© DCA Cyprus). В коде и шаблонах — центр Лимассола (34.68, 33.04), не дом. Перед публикацией искать:
  адреса 192.168.*, домены из CLAUDE.local.md, координаты дома, почту, `eyJ` (токены).
- Данные и их лицензии — `nebo/data/README.md`; types/operators обновляются `tools/update_tar1090db.py`
  (совпадают с tar1090-db байт в байт, своих правок в них нет — дополнения в коде).
- Модули: `sources.py` (adsb.lol / readsb; отдаёт все борта с координатами, «на земле» и радиус
  (только для adsb.lol) отбирает `App.on_board()`), `routes.py` (adsbdb + кеш `/var/lib/nebo/routes.json`,
  проверка правдоподобия маршрута по геометрии), `media.py` (фото, логотипы, флаги — фоновая
  загрузка), `info.py` (типы и авиакомпании), `shapes.py` (силуэты: 13 своих форм-многоугольников, перенесены из
  Nebo Deck `shared/nebo-core/silhouettes.ts` вместе с логикой выбора; `svg_fragment()` даёт тот же SVG,
  что TS-оригинал, рисуются Pillow без cairosvg; эталон для сверки — `node` на самом `.ts`), `inputs.py` (кнопки и тач,
  жесты), `screen.py` (framebuffer по имени, RGB565 через numpy), `ui.py` (отрисовка), `app.py`,
  `web.py` + `www/index.html` (веб-страница, см. ниже), `countries.py` (страна регистрации по hex).
- Данные в `nebo/data/`: `types.json`, `operators.json` (из wiedehopf/tar1090-db), `map.json` (береговая
  линия и аэропорты Natural Earth 10m в районе Кипра; LCA, ECN, AKT добавлены вручную — в NE их нет).
- Экраны: карточка (вариант «B»: текст слева, справа фото и мини-карта) → карта (радар) → список.
  Пользователь выбрал этот вариант 2026-10-11; варианты A и C удалены.
- Управление: кнопки вверх/вниз — самолёт, Enter — следующий экран. Свайпы влево/вправо — самолёт,
  вверх/вниз — экран (в списке — курсор). Тап по фото — QR-код снимка на весь экран (любое касание
  закрывает); тап в любом другом месте карточки (и по фото, если снимка нет) — карта, мёртвых зон нет; на карте тап по самолёту выбирает его,
  по пустому месту — назад; в списке тап по строке открывает самолёт. Через `idle_return` секунд
  без нажатий — снова «ближайший». Резистивный тач при свайпе на миг теряет касание — разрывы
  короче 0,2 с склеиваются (`TOUCH_GAP` в `inputs.py`). Касания пишутся в журнал.
- planespotters.net (фото): User-Agent с контактом из `[media] photo_contact` (почта пользователя;
  использовать разрешено только для planespotters). Условия: имя фотографа всегда видно рядом с фото;
  ссылка — QR-код (у нас по тапу, значок QR в углу фото — компромисс, выбранный пользователем);
  JSON кешировать ≤24 ч; сами снимки на диск не писать и держать в памяти только пока на экране.
- adsb.lol отвечает 429 при опросе раз в 5 с (~10 % запросов), а при 10 с через несколько дней начал
  банить (2026-10-20). С тех пор интервал по умолчанию 60 с, при 429 пауза удваивается до 10 мин
  и учитывается `Retry-After`. Значение в `/etc/nebo/config.toml` на малинке перекрывает умолчание —
  там `interval` тоже надо поправить руками (deploy.sh конфиг не трогает).
- Логотипы: Jxck-S/airline-logos (`flightaware_logos/{ICAO}.png`), рисуются на белой плашке
  (под белый фон). Флаги: flagcdn.com. Оба кешируются в `/var/lib/nebo/{logos,flags}`.
- Шрифты: Roboto Condensed (кириллица есть); знаки → ▲ ▼ — DejaVu (в Roboto их нет), см. `_text()`.
  У IBM Plex Sans Condensed и B612 кириллицы нет.
- Превью без экрана (на малинке): `cd ~/nebo && python3 -m nebo --config /etc/nebo/config.toml
  --png ~/preview/n` → `n-card.png`, `n-qr.png`, `n-radar.png`, `n-list.png`.
  Снимок живого экрана: `python3 ~/nebo/tools/screenshot.py out.png`.
- Скорость (замер 2026-10-11): кадр рисуется ~6 мс + 3 мс перевод в RGB565; передача по SPI ≥25 мс;
  сервис ~3 % одного ядра, 51 МБ. Переписывать на Go ради скорости смысла нет.
- Пакеты на малинке (apt): python3-pil, python3-numpy, python3-qrcode (python3-cairosvg стоит, больше не нужен),
  fonts-dejavu-core, fonts-dejavu-extra, fonts-roboto-unhinted, rsync
  (fonts-ibm-plex и fonts-b612 тоже стоят, не используются).
- Сервис работает от `xtreme` (группы video, input уже есть).

## Веб-страница

- http://<адрес малинки>:8080/ (или `nebo.local:8080`), `[web]` в конфиге (`enabled`, `bind`, `port`).
  Сервер — поток внутри `nebo.service` (`nebo/web.py`), данные берёт у `App`, второй раз ничего
  не запрашивает. Только чтение, табло со страницы не управляется.
- Показывает: все принятые борта на карте Leaflet + OSM (силуэты, кольца 50–400 км, контур
  дальности readsb за сутки — перечитывается раз в 30 с, след и маршрут выбранного; зону 80 км
  пользователь просил не рисовать), таблицу, карточку выбранного
  (логотип, маршрут с флагами, фото, высота/скорость/угол/сближение, тип, борт, сигнал, сырая
  запись readsb) и шапку с приёмом (сообщений/с, сигнал/шум, усиление).
  Галочка «показывать тот, что на табло» — карточка следует за экраном.
- API: `/api/state` (всё разом, раз в 2 с), `/api/plane/{hex}` (сырая запись + описание фото),
  `/shapes.json`, `/data/{stats,receiver,outline,aircraft}.json` (файлы readsb из `/run/readsb`).
- Фото по условиям planespotters: браузер грузит снимок прямо с их сервера, рядом автор и ссылка;
  сервер получает только JSON-описание (тот же кеш, что у табло).
- Порядок фото на странице: planespotters → сам борт с Commons → такой же тип → силуэт. На табло — только planespotters.
- Фото борта с Commons (2026-11-05): `media.RegPhotos`, категория «4X-EKA (aircraft)» → сначала файлы
  с регистрацией в названии, из них недавно добавленные (чаще нынешняя ливрея). Кеш `/var/lib/nebo/reg_photos.json`
  (7 дней / «нет» 3 дня), `[media] reg_photos`. Проверено 2026-10-21 на 10 бортах из приёма: категория с фото у 4.
  Другие источники проверены и отброшены: airport-data.com (прав на фото не даёт, нового почти нет), Openverse
  (медленно, в основном дубли Commons и некоммерческие Flickr), Flickr API (ключ, обязательная надпись, лицензии
  вперемешку), JetPhotos и Airliners.net (API нет).
- Фото типа (2026-10-21, по просьбе пользователя): если у planespotters снимка борта нет (например, 5B-CLZ,
  Tecnam P2008), страница показывает фото такого же типа с плашкой «не этот борт · такой же тип: <статья>».
  `media.TypePhotos`: название типа из tar1090-db как есть («BOEING 737 MAX 8», не `_pretty`) → статья
  английской Википедии (варианты названия без дефиса и без хвоста, затем поиск со сверкой номера модели;
  Dash 8, E-Jet, CRJ — вручную в `TYPE_ARTICLES`) → её главная свободная картинка (PageImages) → автор и
  лицензия с Commons. Кеш описаний `/var/lib/nebo/type_photos.json` (30 дней / «нет» 7 дней),
  `[media] type_photos`. На табло — по-прежнему силуэт.
- Страна регистрации — по hex-адресу (`nebo/countries.py`, блоки адресов ИКАО; сверено с регистрациями
  tar1090-db, блоки Мальты, Сан-Марино, Монголии в жизни шире — расширены). В шапке карточки: флаг и
  название (`Intl.DisplayNames` браузера), у частных бортов без авиакомпании — вместо логотипа.
- Проверка вёрстки с Mac: headless Chrome не видит малинку (macOS «Локальная сеть» → ERR_ADDRESS_UNREACHABLE),
  нужен туннель `ssh -L 18080:127.0.0.1:8080`. Окно headless-Chrome не уже 500 px — телефон
  проверять во фрейме шириной 375 px.

  туннель `nebo` управляется из панели). Маршрут: nebo.<домен> → http://localhost:8080.
- Защита: приложение Cloudflare Access (команда `<команда>`, вход одноразовым кодом на почту пользователя,
  сессия месяц) + «Protect with Access» в маршруте туннеля — `cloudflared` сам проверяет пропуск (AUD).
  Проверено: без входа и с поддельным пропуском — 302 на <команда>.cloudflareaccess.com.
- Без защиты публиковать нельзя: страница выдаёт координаты дома и умеет переключать донгл.
- HTTPS нужен для AR (камера, компас, GPS в браузере — только в защищённом контексте).
  В домашней сети по-прежнему работает http://<адрес малинки>:8080 (без AR).
- Вариант с certbot + DNS-01 и A-записью на домашний адрес малинки отброшен (certbot удалён); роутер
  при этом не блокирует публичные имена с домашними адресами — проверено через nip.io.

## AR для телефона (/ar)

С 2026-10-20: https://nebo.<домен>/ar (вкладка «AR»). Только по HTTPS — камера, датчики и GPS
браузер даёт лишь защищённому сайту (http://localhost тоже считается защищённым — для проверок).
- Камера фоном; ориентация — `deviceorientationabsolute` (Android Chrome) или `deviceorientation` +
  `webkitCompassHeading` (iPhone: alpha относительная, сдвиг до севера сглаживается); кватернион Z-X'-Y''
  по W3C, сглаживание nlerp. Магнитное склонение `DECLINATION = 5.5` (Кипр, к востоку) — в ar.html.
- Наблюдатель — GPS телефона (иначе точка дома), самолёты — /api/state?view=1 раз в 2 с, между опросами
  сдвиг по курсу и скорости (seen_pos + время с опроса). Угол над горизонтом с поправкой на кривизну Земли.
- Экран: кружок вокруг места каждого самолёта в кадре (ближе — крупнее), синий — «в прицеле» (ближе всех к
  центру кадра); стрелки по краю к четырём ближайшим вне кадра (плашки не налезают друг на друга); радар в
  правом верхнем углу (вид сверху, камера вверх, сектор обзора, «С» на ободе); панель внизу — самолёт
  в прицеле, иначе ближайший с подсказкой «← 35°, ↑ выше 10°»; тап по подписи закрепляет. Ссылки: карточка
  `./#hex` (главная страница открывает борт по адресу) и трек на globe.adsb.lol.
- Проверка без телефона: headless Chrome через туннель `ssh -L 18080:127.0.0.1:8080` (localhost — защищённый
  контекст), во временную копию ar.html на малинке дописать скрипт: `DeviceOrientationEvent.requestPermission`
  → 'granted' (в свежем Chrome он есть и в headless висит), `getUserMedia` → `canvas.captureStream()`,
  клик по «Начать» и `deviceorientationabsolute` с нужными alpha/beta; потом `rsync nebo/www/` обратно.
- Блокировку сна экрана (wakeLock) не ждать через await — если браузер не ответит, AR не стартует.
- Калибровка: перекрестие на видимый самолёт → тап по подписи → `headingCal` (вычитается из alpha);
  щипок — угол обзора по длинной стороне экрана (по умолчанию 63°). Оба — в localStorage `nebo.ar`.
- Математика проверена в node на синтетике (север/запад/наклон/альбомная ориентация/за спиной).
  2026-10-21 пользователь проверил на iPhone с балкона: кружки практически совпадают с самолётами
  (webkitCompassHeading при вертикальном телефоне работает). Проверка на улице — впереди. Ошибка GPS на угол почти
  не влияет (30 м на 20 км — 0,1°), главное — компас: у стен и металлических перил он врёт на градусы.
  На Android не проверялось (своих Android у пользователя нет).

## Переключение донгла со страницы (receiver.py)

- Видимая страница судов (`/api/ships?view=1`) запускает `ais-catcher.service`, видимая страница
  самолётов (`/api/state?view=1`) — `readsb.service`; фоновые вкладки не считаются. Между
  переключениями не меньше 20 с. Страницу судов не запрашивали 120 с (`[web] ships_idle_return`) —
  донгл сам возвращается к самолётам (так же и после ручного `systemctl start ais-catcher`).
- Права: `deploy/50-nebo-receiver.rules` → `/etc/polkit-1/rules.d/` — пользователю xtreme можно
  только `start` этих двух юнитов (stop — нет, проверено). sudo nebo нельзя (NoNewPrivileges).
- Пока антенна у судов, табло пишет «Антенна слушает суда». Проверено 2026-10-20: переключение
  туда и обратно, за 25 с — 18 настоящих судов.
- `ais-catcher.service` упорядочен `After=readsb.service`: при переключении systemd сначала
  останавливает один, потом запускает другой (иначе readsb падал на занятом донгле, +15 с).
- Любая видимая страница самолётов (второй монитор, телефон) тянет донгл обратно — две видимые
  страницы разных видов будут переключать его раз в 20 с.
- `[web] receiver_switch = false` — отключить.

## Суда (AIS) на малинке

Сделано 2026-10-20. Донгл один:
либо самолёты (readsb, 1090 МГц), либо суда (AIS-catcher, 162 МГц).

- AIS-catcher v0.70 (коммит 8833c64) собран из исходников: `~/src/AIS-catcher/build`, `cmake .. && make -j4`
  (нужен cmake; SSL и SQLite не нужны), бинарник `/usr/local/bin/AIS-catcher`. Пользователь `aiscatcher`.

  Параметры `deploy/ais-catcher.default` → `/etc/default/ais-catcher` (ppm 31, координаты дома,
  веб-сервер AIS-catcher на 127.0.0.1:8100 — ключ `IP_BIND`). `deploy.sh` ставит юнит, не запуская.
- **AIS-catcher по умолчанию отправляет принятое в сообщество aiscatcher.org** (`-X on`). В юните и в
  `tools/demo/ships.py` стоит `-X off`. 2026-10-20 тестовый запуск без `-X off` ~10 с был подключён к их
  хабу и мог отправить выдуманные суда из `ais_fake.py`; демо на Mac 2026-10-19 запускалось без `-X off`
  и, вероятно, делилось реальным приёмом.
- Страница http://<адрес малинки>:8080/ships (`nebo/www/ships.html`, данные — `nebo/ships.py`): карта
  со значками по классам AIS-catcher (стрелка — идёт, кружок — стоит, ромб — знак), след выбранного
  (`/api/path.json` AIS-catcher), карточка (флаг, тип, статус, назначение, ETA, размеры, MMSI/IMO,
  ссылки MarineTraffic и VesselFinder), таблица. `/ships#MMSI` открывает судно. Когда AIS-catcher
  не работает — плашка «донгл слушает самолёты» с командами переключения. Расстояние от дома
  считает nebo: AIS-catcher без своего приёма отдаёт `distance: null`.
- `[web] ais_url` в конфиге (по умолчанию http://127.0.0.1:8100). Стили обеих страниц — `www/nebo.css`.
- Фото судов (2026-10-20): Wikimedia Commons, `media.ShipPhotos`. Категория `IMO N` (около 36 тыс.)
  или `MMSI N` (около 4 тыс.) → в ней подкатегория судна → снимки; берётся файл с именем судна в названии.
  Лицензии CC — на странице автор, лицензия и ссылка на файл; превью браузер грузит с
  upload.wikimedia.org, nebo кеширует только описание (`/var/lib/nebo/ship_photos.json`, 7 дней /
  «нет» 3 дня). `[media] ship_photos`, `commons_contact` (в User-Agent — адрес репозитория, не почта).
  MarineTraffic, VesselFinder, ShipSpotting не использовать: открытого API нет, автоматическое
  скачивание запрещено их условиями. Покрытие Commons — крупные и известные суда; яхты и портовая
  мелочь обычно без фото. На реальном приёме у Лимассола покрытие ещё не замерялось.
- 2026-10-20 в проверочных curl-запросах к Wikimedia по ошибке ушла почта пользователя в User-Agent
  (несколько запросов). Почта — только для planespotters.
- Проверка без антенны: AIS-catcher читает NMEA по UDP, донгл не нужен —
  `AIS-catcher -X off -x 127.0.0.1 10110 -N 8100 IP_BIND 127.0.0.1 -o 0` и `python3 tools/ais_fake.py`
  (выдуманные суда у Лимассола, сообщения 1, 5, 18, 24, 21).
- Не убивать процессы через `pkill -f` с текстом, который есть в собственной команде ssh — убивает сессию
  (`pkill -x AIS-catcher`).

## Ограничения по железу

- Экран 3,2" физически закрывает контакты 1–26, включая штатные I2C (SDA/SCL).
  Свободны контакты 27–40 (около девяти GPIO).
- Если понадобятся LCD 1602 или MPU6050 одновременно с экраном — поднять
  программный I2C на свободных ножках через `dtoverlay=i2c-gpio`.
- Экран 1,8" можно посадить на второй канал SPI (SPI1), который выведен на свободные контакты.
- USB, аудиогнездо 3,5 мм, Bluetooth и разъём камеры экраном не заняты.
- Как подключается динамик из набора Freenove, не выяснено — смотреть учебник.
  Запасной вариант для звука — гнездо 3,5 мм или USB.
